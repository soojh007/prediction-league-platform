# Prediction League Platform

A customizable football prediction platform for private groups, offices, schools, fan clubs, and communities.

The goal is to evolve from a single World Cup prediction app into a reusable service where league admins can create their own prediction competitions, choose football tournaments, invite players, and run leaderboards with minimal setup.

## Core Idea

One platform supports many private leagues.

Users can:

- Create or join private leagues
- Choose competitions such as World Cup, Premier League, Champions League, Euros, AFCON, or friendlies
- Predict match scores
- Track overall and competition-specific leaderboards
- Receive reminder emails before matches

League admins can:

- Create a league
- Choose the competition and season
- Invite users by code or link
- Configure scoring rules
- View members and predictions
- Post announcements
- Optionally pay a small hosting/admin fee

## First MVP

Keep the first version focused:

1. Users can register and login.
2. Admins can create a private league.
3. Each private league selects one competition.
4. Fixtures sync from API-Football.
5. Users predict matches.
6. Leaderboards are calculated per private league.
7. Overall leaderboard can still exist across the platform.
8. Email reminders are opt-in.

## Render + PostgreSQL Deployment

This project is prepared for Render using:

- `render.yaml` for the web service and PostgreSQL database
- `build.sh` for install, static collection, and migrations
- `gunicorn` as the production server
- `WhiteNoise` for static files
- `DATABASE_URL` for PostgreSQL

### Required Render Environment Variables

Render can generate or inject most of these from `render.yaml`, but check them before the first deploy:

```text
DEBUG=False
SECRET_KEY=<generated by Render>
DATABASE_URL=<from Render PostgreSQL>
ALLOWED_HOSTS=.onrender.com,your-domain.com
CSRF_TRUSTED_ORIGINS=https://your-render-service.onrender.com,https://your-domain.com
FOOTBALL_API_KEY=<your API-Football key>
SECURE_SSL_REDIRECT=True
SECURE_HSTS_SECONDS=31536000
```

For privacy-friendly traffic analytics, configure either Cloudflare Web Analytics or Plausible:

```text
CLOUDFLARE_ANALYTICS_TOKEN=<Cloudflare Web Analytics token>
PLAUSIBLE_DOMAIN=predictionleague.site
```

Leave both blank to disable analytics, such as during local development. If you use a self-hosted Plausible instance, also set `PLAUSIBLE_SCRIPT_SRC`.

For password reset emails, also configure SMTP:

```text
EMAIL_BACKEND=django.core.mail.backends.smtp.EmailBackend
EMAIL_HOST=<smtp host>
EMAIL_PORT=587
EMAIL_HOST_USER=<smtp user>
EMAIL_HOST_PASSWORD=<smtp password>
EMAIL_USE_TLS=True
DEFAULT_FROM_EMAIL=Prediction League <no-reply@your-domain.com>
CONTACT_EMAIL=hello@your-domain.com
```

### Deploy Steps

1. Push this project to GitHub.
2. In Render, create a new Blueprint from the repository.
3. Confirm the PostgreSQL database is attached.
4. Update `CSRF_TRUSTED_ORIGINS` to the real Render URL after the service is created.
5. Add `FOOTBALL_API_KEY`.
6. Deploy.
7. Create the first admin user from Render Shell:

```bash
python manage.py createsuperuser
```

8. Open `/organiser/login/` for organiser access.

### Local Production Check

You can run a local production-style check:

```bash
DEBUG=False \
SECRET_KEY=local-production-test-secret-with-more-than-fifty-characters-12345 \
ALLOWED_HOSTS=127.0.0.1,localhost \
CSRF_TRUSTED_ORIGINS=http://127.0.0.1:8001,http://localhost:8001 \
SECURE_HSTS_SECONDS=31536000 \
python manage.py check --deploy
```

The deploy check may still warn about HSTS subdomains/preload. Keep those off until every future subdomain is definitely served over HTTPS.

## Recommended Business Model

Charge the league organiser instead of every player.

Suggested tiers:

- Free: up to 10 players, one league
- Small League: one-time fee for up to 50 players
- Pro League: larger groups, custom branding, advanced admin tools
- White Label: custom logo, landing page, and private domain/subdomain

Avoid positioning this as betting. Use:

- prediction league
- private competition
- leaderboard challenge
- football pool

Do not use:

- betting
- wagering
- gambling
- cash betting

## Product Direction

This should become a multi-tenant app:

- One application
- One database
- Many users
- Many leagues
- Many competitions

Data should separate users, leagues, competitions, matches, predictions, scoring rules, and payments.
